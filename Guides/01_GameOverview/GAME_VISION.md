## 한 줄 정의

> **드래프트로 5캐릭을 뽑아 라인에 배치하고, 라운드 사이 글로벌 골드로 아이템을 사며, AI가 싸우는 걸 관전하고 적응해 나가는 오토배틀러 MOBA.**

플레이어는 **직접 조종하지 않는다**. 플레이어는 *지휘관/코치*다. 전투는 AI가 수행하고, 플레이어는 **드래프트 · 라인 배치 · 아이템 빌드** 라는 전략적 의사결정으로 승패를 만든다.

## 코어 루프

```
[게임 시작]
  드래프트 (밴/픽) → 5 캐릭터 선택
        │
        ▼
  라인 배치 (5 캐릭터를 Top/Mid/Bottom 에 분배, 라인당 0~2)
        │
        ▼
┌──▶ [라운드 진행 — 플레이어 관전]
│     · AI가 라인 푸시 / 전투 / 타워 공격
│     · 글로벌 골드 획득: 미니언, 적 캐릭터 킬, 타워 파괴
│     · 타워/CC HP는 누적 (라운드 넘어 유지)
│        │
│        ▼
│  [라운드 종료]
│     · 캐릭터 선택 창 + 상점 버튼 동시 노출
│     · 상점: 내 5캐릭 아이콘 → 클릭 → 해당 캐릭터 상점 → 아이템 구매·착용
│        │
│        ▼
│  [재배치 단계]
│     · 직전 라운드 2라인 이상 패배한 팀만 캐릭터 재배치 가능
│     · (라인 패배 = 그 라인에 배치한 캐릭터가 전부 먼저 사망)
│        │
└────────┘  (라운드 반복)
        │
        ▼
  [승리] 상대 커맨드센터(CC) 먼저 파괴
```

## 라운드 모델 (확정 — "맵 누적")

| 요소 | 라운드 간 처리 |
|---|---|
| **타워 / CC HP** | **누적** — 한 번 받은 데미지는 유지. 여러 라운드에 걸쳐 라인이 뚫리고 CC가 무너짐. |
| **캐릭터** | **리셋·재배치** — 매 라운드 5캐릭이 다시 배치됨 (라운드는 "전투 한 판 + 상점 휴식"의 반복) |
| **골드** | **누적** — 글로벌 풀에 쌓임 |
| **아이템/빌드** | **누적** — 한 번 산 아이템은 유지 |

→ 정상 MOBA의 "꾸준한 누적 압박" + 오토배틀러의 "라운드 단위 적응"이 맞물린다.
→ **두 개의 분리된 트랙**:
  - *라인 승패* (= 캐릭터 생존) → 재배치 권한을 결정
  - *실제 진격* (= 타워/CC 누적 데미지) → 게임 승리를 결정
  - 한 라인을 "졌지만"(내 캐릭 전멸) 그 사이 적 타워는 깎았을 수 있다 — 의도된 뉘앙스.

> **열린 디테일**: 캐릭터가 라운드 간 *완전* 리셋인지, 생존 캐릭터의 일부 상태(예: 경험치/레벨)가 유지되는지는 미정. MVP는 완전 리셋로 시작.

## 플레이어 동사 (Player Verbs)

플레이어가 게임 중 실제로 하는 행동은 **단 둘**로 축약된다:

1. **상점에서 아이템 구매·착용** (라운드 사이)
2. **라인에 캐릭터 배치** (드래프트 직후 + 조건부 재배치)

(+ 드래프트의 밴/픽 — 게임당 1회)
(보류 검토: 라운드 중 "소환사 주문" 류 실시간 개입 — 나중에 추가 여부 결정)

→ 입력이 적다는 것은 **각 결정의 무게가 크다**는 뜻. 그래서 ↓ 디자인 기둥이 중요하다.

---

## 디자인 기둥 (Design Pillars)

### 1. 전략이 곧 플레이
기계적 조작(에임·콤보)이 아니라 **드래프트 · 배치 · 빌드의 의사결정**이 승패를 만든다. 손이 아니라 머리로 이기는 게임.

### 2. 관전이 읽혀야 한다 (가장 중요)
플레이어가 **관전**하므로, "**내 선택이 이 결과를 만들었다**"가 시각적으로 명료해야 전략적 쾌감이 생긴다. AI가 아무리 똑똑해도 화면이 난전 덩어리면 인과가 안 읽힌다.
→ **미니맵 · 라운드 결과 요약 · 데미지 피드백**은 "추가 기능"이 아니라 **장르 필수 인프라**.

### 3. AI가 캐릭터의 개성을 연기한다
입력이 적으므로, 캐릭터 아키타입(카이팅 원거리 / 돌진 근접 / 지원)이 **AI 행동으로 드러나야** 빌드·조합 선택이 보답받는다. "내가 카이팅 조합을 짰다 → AI가 실제로 치고 빠진다 → 이겼다"의 연결.

### 4. AI로 만든, AI를 지휘하는 게임 (프로젝트 정체성)
개발은 멀티 에이전트 + MCP로, 게임은 플레이어가 AI 군단을 지휘하는 구조 — **개발 방법론과 게임 테마가 일관**된다. (이 메타 일관성은 발표의 핵심 서사) → 멀티에이전트/MCP/연구일지(TIMELINE) 유지.

## 핵심 규칙 디테일

### 라인 승패 판정
- **패배 조건**: 그 라인에 배치한 캐릭터가 **전부 먼저 사망**.
- 승패는 *캐릭터 생존*으로 판정 (타워 데미지와 별개 트랙).

### 조건부 재배치
- **2라인 이상 패배한 팀만** 다음 라운드 캐릭터 재배치 가능.
- 효과: 패자는 *적응*(특정 라인 카운터), 승자는 *잠금*(이긴 세팅 유지) = 소프트 캐치업.
- ⚠️ **튜닝 1순위**: 이기는 플레이어가 "잘 큰 캐릭을 다른 라인으로 옮기고 싶어도 못 하는" 답답함이 될 수 있음. 의도된 제약인지 플레이테스트로 확인.

### 글로벌 골드 경제
- **공유 풀** (팀 전체가 하나의 골드 풀, 5캐릭에 분배 구매) — TFT식.
- 획득원: 미니언, 적 캐릭터 킬, 타워 파괴.
- ⚠️ **열린 결정**: 이긴 라인에 추가 골드(스노볼) vs 균등 분배(컴백 여지). MVP는 균등으로 시작 후 튜닝.

## 임계 경로 로드맵

각 Slice는 **독립적으로 데모 가능** (= 연구일지/발표에 좋음).

### Slice 0 — 심장박동 증명 ⭐ ✅ 완료 (2026-06-04, 목표 초과)
- 캐릭터 **5종** + 라인 배치 + 골드(킬/파괴/라운드 수입) + **아이템 5종 스탯 강화** + 라운드 간 재구매(유닛 귀속 누적) + 상점 팝업(유닛선택→아이템, ★추천)
- 드래프트/밴/조건부재배치/미니맵 **생략** (계획대로)
- **검증 질문**: *"아이템 사고 배치 잘하면, 원래 질 라운드를 이길 수 있는가?"* → 시스템 구현·동작 확인 완료. (밸런스 수치 튜닝은 후속)

### Slice 1 — 가독성
- 라운드 결과 요약, 데미지 숫자, **미니맵**. "관전이 읽힌다" 달성.

### Slice 2 — AI 깊이
- 타겟 선정 + 아키타입별 카이팅(원거리 빠지고/근접 붙고). 빌드·조합이 보답받는 지점.

### Slice 3 — 정문
- 드래프트/밴 UI + 로스터 확장(8~10 캐릭터).

### Slice 4 — 매크로
- 라인 스위칭(지원 로밍) + 조건부 재배치 룰 완성.
